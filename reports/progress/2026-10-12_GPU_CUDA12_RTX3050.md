# Chạy model trên RTX 3050 với CUDA 12.6 — 12/10/2026

## Nguyên nhân và cách xử lý

Máy kiểm tra có RTX 3050 Laptop 6 GB, driver NVIDIA 566.14 (`nvidia-smi`: CUDA 12.7). `.venv-ml` dùng Python 3.14 + ONNX Runtime GPU 1.31.0/CUDA 13; khi tạo CUDA session trả lỗi 801 rồi ORT tự khởi tạo lại bằng CPU. NVIDIA yêu cầu driver ≥580 cho CUDA 13.x; ORT 1.21–1.26 dùng CUDA 12.8, cũng cao hơn mức driver hiện tại. Tham khảo [NVIDIA CUDA compatibility](https://docs.nvidia.com/deploy/cuda-compatibility/minor-version-compatibility.html) và [bảng ORT CUDA EP](https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html).

Đã tạo `.venv-ml-gpu` bằng Python 3.12.9 từ NuGet chính thức, cài `backend/requirements-ml-cuda12.txt` (ORT GPU 1.20.2, CUDA 12.6, cuDNN 9.5) và `backend/requirements-ocr.txt`. CUDA runtime trả `cudaGetDeviceCount=0, count=1`; test ONNX đầu tiên tạo CUDA session và chạy inference thành công. Không thay driver hệ thống.

`backend/app/ml/__init__.py` nạp DLL CUDA 12 từ gói NVIDIA cho ORT 1.20 (chưa có `preload_dlls`), thêm `VNSTORE_ML_DEVICE=cuda`: kiểm tra CUDA EP đứng đầu session và gọi `disable_fallback()`. Nếu CUDA không khởi tạo, ứng dụng trả lỗi thay vì chấp nhận CPU session. Test cố tình dùng lại ORT 1.31/CUDA 13 xác nhận lỗi “từ chối CPU fallback”. Silero VAD và ba session RapidOCR cũng dùng CUDA trong chế độ này; đã xác nhận các session OCR báo `CUDAExecutionProvider` đầu tiên.

Không bật `session.disable_cpu_ep_fallback=1`: graph SigLIP2 cần một số node shape trên CPU và không thể khởi tạo với lựa chọn đó. ONNX Runtime vẫn dùng CPU cho node shape nhỏ, tiền xử lý ảnh/âm thanh, keyword và ghép kết quả. Kiểm tra trên bảo đảm model không chuyển **toàn bộ session** về CPU; không đồng nghĩa mọi phép tính đều trên GPU.

ORT profiling của một lượt inference xác nhận node tính toán chính chạy trên CUDA: SigLIP2 có 473 node CUDA/3 node CPU; encoder PhoWhisper-small có 403 node CUDA/132 node CPU. Thời gian kernel ghi trong profile lần lượt là CUDA 183.482/33.248 µs và CPU 48/1.529 µs. Profile có overhead, chỉ dùng để xác nhận phân bổ provider, không dùng làm số đo độ trễ ở bảng dưới.

Đo một ảnh catalog và một clip FLEURS, 5 lượt sau warm-up, lấy trung vị. CPU dùng `.venv-ml` Python 3.14/ORT 1.31; GPU dùng `.venv-ml-gpu` Python 3.12/ORT 1.20. Cùng checkpoint, cùng dữ liệu; khác phiên bản runtime nên đây là smoke hiệu năng, chưa phải benchmark nghiệm thu.
